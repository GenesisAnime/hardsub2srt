# Phase 5 local OCR execution

`hardsub2srt.py phase5-run` is the opt-in path for executing the product OCR
pipeline against the already frozen Phase 5 dataset and time-aligned reference
groups. Ordinary CLI invocations retain their existing defaults. This command
does not train a model, upload data, or produce a Phase 6 release decision.

## What it runs

The runner requires a strict `ocr-phase5-execution-plan-v1` JSON file. It checks
the existing Phase 2 active review-event chain, human-reviewed metadata, frozen
split, evaluation plan, timed reference manifest, full input-media SHA-256 values,
two hash-pinned profiles matching the frozen baseline/candidate IDs, and a
separately reviewed local execution-rights receipt. The receipt's exact SHA-256
must also appear in `schemas/trusted-phase5-execution-receipts-v1.json`. That
registry is empty by default, so real execution stops until a project maintainer
has reviewed the exact scope and explicitly pins its receipt hash.

The runner invokes only the repository's `hardsub2srt.py` through a fixed
argument vector. It does not accept a shell command, executable path, extra
arguments, plugin, or arbitrary engine name from the plan. Each frozen engine
profile runs against every media group in the plan. Output goes into a fresh
fresh staging directory under an existing local output parent, outside all
input, model, reference, dataset, and repository roots. It is published only
after the SRTs parse, stats identify the expected media/profile, and inputs and
model assets still match their original hashes.

```powershell
py -3 hardsub2srt.py phase5-run --plan "D:\local-only\phase5-execution-plan.json"
```

Paths in the plan, profile, and rights receipt must be absolute local fixed-drive
paths. UNC/mapped drives, OneDrive output, symlinks, junctions, reparse points,
existing output paths, and input/output overlap are rejected. A failed or
partial run removes only the fresh staging folder created by that invocation.

## Offline OCR profiles

Each profile uses `schemas/ocr-offline-profile-v1.schema.json`. It pins the
complete file inventory in one local EasyOCR model directory with SHA-256 values.
Every file in that directory must appear exactly once; every `.pth`/`.pt` model
weight is therefore pinned. The only second-engine choices are `none` and
`ppocrv5`. PP-OCRv5 requires exact local detector, recognizer, and dictionary
files with hashes; there is no default resolver or fallback in experiment mode.
The runner fixes the application OCR mode to this allowlisted second-engine
route. Unknown engines stop before media access.

EasyOCR is constructed with `download_enabled=False` and the explicit model
directory. RapidOCR receives explicit local model paths. GPU remains the
default preference; a CPU profile must say `device_preference: "cpu"` and the
runner passes `--cpu`. The recorded device comes from the product stats; the
profile records requested preference separately. The field describes the
primary reader's configured device. ONNX values are session-configured provider
lists, not per-node execution measurements. The offline-only stats block is
additive; ordinary stats retain their prior shape.

At the application layer, the offline child process blocks Python socket APIs,
sets common model/package offline environment flags, and all managed model
loaders use pinned local files with downloads disabled. FFprobe and FFmpeg are
limited to local file protocols (plus the local stdout pipe used for decoded
frames); media with an embedded subtitle stream is rejected because it bypasses
OCR. This is not an OS-level network sandbox: a native library or child process
could theoretically bypass Python socket blocking. For a strict air gap, run on
a machine/session whose OS network access is disabled. No Phase 5 command
installs packages or accesses a model registry.

## Rights attestation and trust pin

The human receipt uses `schemas/ocr-phase5-execution-rights-v1.schema.json` and
binds the approved scope to hashes for the dataset, metadata, frozen split,
evaluation plan, preparation report, timed references, every media group, and
both model profiles. It records a reviewer, authority, timestamp, and scope.
The receipt is not generated by the runner. The reviewer must make and document
the decision independently; a project maintainer then adds the SHA-256 of the
exact receipt bytes to the separate pinned registry.

These are application attestations. Hashes and a reviewer string cannot prove
legal permission or independently authenticate the person. In particular, the
runner always writes `rights_verified: false` and `phase6_eligible: false`.
Its generated `phase5-execution-receipt-v1.json` is an execution record only;
it is not eligible as a rights receipt, pinned trust evidence, or Phase 6 PASS.

## Plan fields

See `schemas/ocr-phase5-execution-plan-v1.schema.json` for the strict shape. The
plan names the validated `verified-ocr-dataset-*`, metadata, frozen split,
`PREPARED_NOT_RUN` experiment report, timed-reference manifest, receipt, and
output parent. It lists exactly one media file per frozen source/episode group,
each with the full SHA-256 matching both the reference manifest and actual file.
It lists exactly two profile rows, keyed by the frozen baseline and candidate
engine IDs. The plan has no command or free-form OCR argument field.

The reviewer receipt's `media_sha256s` object maps SHA-256 of each canonical
source/episode group key to that group's full media SHA-256. Its
`profile_sha256s` object maps the two frozen engine IDs to exact profile-file
hashes. All other receipt bindings are direct SHA-256 values of the corresponding
validated files.

The canonical group key is compact UTF-8 JSON for a two-item array:
`[source_id, episode_id]`. Before encoding, each ID is Unicode NFC-normalized,
internal whitespace is collapsed to one space, and text is case-folded. The
group-map key is SHA-256 of those exact compact JSON bytes (no trailing
newline), matching the frozen Phase 5 split implementation.

## Output and limits

The output contains a `prediction-manifest-v1.json` accepted by the existing
video measurement adapter, plus SRT/stats pairs and a local execution receipt.
The execution receipt records an optional Git commit, a deterministic digest of
all product Python sources (including untracked files) and behavior dictionaries,
Python/package/tool hashes and versions, and hashes of the effective child
environment. Git metadata is optional, so the same bundle digest works in the
Desktop copy without `.git`. Proxy variables and Python path/startup overrides
are removed from the child environment; only an allowlisted set of runtime
variables is passed and their values are recorded as SHA-256 digests. Python
starts with `-S`; the bootstrap blocks sockets before adding only the
interpreter's global package directories, without executing `.pth`,
`sitecustomize`, or user-site startup code. Runtime packages must be installed
in those global directories. The
receipt also binds profile/model/input/output hashes, the reader's configured
device, session-configured provider metadata, and elapsed time. It
does not contain subtitle text or
reference text beyond what the normal local SRT/stats artifacts themselves
contain. Keep the output local and outside synchronized/shared folders.

The device/provider fields describe reader and session configuration; they do
not profile individual inference nodes or prove hardware executed them. A
timeout terminates the complete child process tree before staging cleanup; if
the runner cannot confirm termination, it preserves the unpublished staging
folder instead of deleting files a process might still be writing. The
execution record does not independently verify execution at the OS/hardware
boundary, identity of the reviewer, legal use rights, or correctness of the
time-aligned references. Video timestamps retain the product's existing
frame-index/reported-FPS basis and its VFR limitation. Existing `ocr_video_eval`
results remain measurement-adapter output; they do not unlock Phase 6. This
workflow currently performs inference only: it does not train or alter model
weights.
